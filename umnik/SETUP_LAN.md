# Офисный индексатор архива

Этот компьютер (`192.168.200.20` или другой ПК у шары `D:\Общая_Рабочая`) **не отвечает
на поиск CRM**. Его задача — читать PDF, обновлять `catalog.db` + Chroma и сами
заливать снимок индекса в S3. Умный умник на облачном VPS забирает снимок и
обслуживает `/crm/lookup` и `/crm/chat`.

В `umnik/.env`:

```
UMNIK_ROLE=indexer
INDEX_S3_BUCKET=ch-crm-umnik-index
INDEX_S3_ENDPOINT=https://storage.yandexcloud.net
INDEX_S3_ACCESS_KEY=...
INDEX_S3_SECRET_KEY=...
```

`start.bat` как раньше поднимает `mcp_server.py --http`. Watcher раз в ~5 минут
сканирует шару; если индекс изменился — публикует `manifest.json` + `latest.tar.gz`.

CRM в облаке указывает `UMNIK_URL` на query-умник, **не** на этот ПК.

OpenRouter-ключ на индексаторе нужен только для распознавания планировок
(таблицы комнат/м²). Локальный Qwen / Claude по подписке для поиска CRM больше
не используются. Ниже — старые заметки про LAN-чат, если оставите веб-интерфейс
на этом ПК для себя; сотрудники ищут в CRM.

## 1. Настройка сервера (один раз)

### Шаг 1. Войти в Claude по подписке


CLI уже установлен (`npm install -g @anthropic-ai/claude-code`). Осталось войти:

```bash
claude login
```

Откроется браузер, вводите логин и пароль своей учётной записи Anthropic.
Токен ляжет в профиль Windows, и сервер будет отвечать от вашей подписки.

Проверить: вкладка **«Сеть»** в веб-интерфейсе, строка «Claude по подписке».

### Шаг 2. Дописать в `.env`

```
WEB_USERS=ivan:пароль1,petr:пароль2,anna:пароль3
MCP_TOKEN=придумай-длинную-строку
CLAUDE_CLI_MODEL=opus
CLAUDE_MAX_PARALLEL=2
```

- `WEB_USERS` — кто заходит в веб-чат. **Пока строка пустая, чат открыт всей сети без пароля.**
- `MCP_TOKEN` — пароль для тех, кто подключает свой Claude Desktop к архиву.
- `CLAUDE_CLI_MODEL` — модель Claude Code CLI. Alias `opus` сам берёт актуальную Opus на аккаунте.
- `CLAUDE_MAX_PARALLEL` — сколько вопросов к Claude выполняется одновременно.
  Подписка одна на всех, поэтому больше 2–3 ставить не стоит.

`OPENROUTER_API_KEY` в `.env` остаётся, но чат его больше не трогает —
он нужен только для распознавания планировок при индексации.

### Шаг 3. Прокси до Anthropic

Ничего настраивать не нужно: берётся `OPENROUTER_PROXY` из `.env`.
Сервер поднимает локальный мост `127.0.0.1:17880`, который сам подставляет
логин и пароль прокси, и передаёт CLI уже чистый адрес без пароля
(`proxy_auth_bridge.py`, `claude_cli.proxy_env`). Локальная сеть идёт мимо прокси.

### Шаг 4. Запустить

`start.bat` **от имени администратора** — пропишет правила брандмауэра
для портов `7860` (чат) и `7861` (MCP). Администратор нужен только один раз.

`autostart.bat` от администратора — сервер будет подниматься сам при старте Windows.
Без него архив доступен сети, только пока кто-то держит окно `start.bat`.

## 2. Файл для общей папки

Скопируйте **`Архив.bat`** из `D:\Scan_Pdf` в `D:\Общая_Рабочая`.

Дальше любому сотруднику достаточно двойного клика:

- сервер работает → сразу открывается `http://192.168.200.20:7860`;
- сервер не отвечает, а файл запущен **на самом сервере** → сначала поднимет сервер, потом откроет чат;
- сервер не отвечает с чужого ПК → покажет, что проверить.

Если у сервера сменился IP — поправьте строку `SERVER=` в начале файла.
Текущий адрес показывает на сервере команда:

```bash
D:\Scan_Pdf\.venv\Scripts\python.exe net.py
```

## 3. Что видит сотрудник

Открывает `http://192.168.200.20:7860`, вводит логин и пароль, выбирает собеседника:

| Собеседник | Чем считает | Ограничения |
|---|---|---|
| **Claude Opus — подписка** | подписка владельца сервера, модель `opus`; при нужде зовёт Qwen на PDF и планировки | лимиты подписки общие на всех |
| **Локальный ИИ (Qwen2.5 14B)** | видеокарта сервера; запасной чат, если Claude не залогинен | нет, но отвечает проще |

Кнопка **«Начать заново»** сбрасывает разговор — Claude забывает предыдущие вопросы.
Каждый пользователь ведёт свой диалог: сессии не пересекаются.

Из сети архив доступен **только на чтение**. Кнопки «Открыть в Проводнике»
и вкладка «MCP Claude» по сети выключены — они открывают окна на экране сервера.

## 4. Свой Claude Desktop вместо веб-чата

Для тех, у кого **своя подписка Claude Pro**: их вопросы не расходуют лимит сервера.
На их ПК нужен только **Node.js**, проект копировать не надо.

Готовый конфиг сервер генерирует сам:

```bash
D:\Scan_Pdf\.venv\Scripts\python.exe mcp_server.py --install
```

Файл появится в `D:\Scan_Pdf\mcp\client_claude_desktop_config.json` — его содержимое
сотрудник вставляет себе в `%APPDATA%\Claude\claude_desktop_config.json`
и перезапускает Claude Desktop. Так же настраивается Cursor (`~\.cursor\mcp.json`).

## 5. Что защищено

| Проверка | Где |
|---|---|
| У Claude отобраны Bash, PowerShell, REPL и WebFetch (`--restricted`) | `claude_cli.py` |
| Claude видит только инструменты архива (`--strict-mcp-config`) | `claude_cli.py` |
| Файловые операции заперты в архив и проект (`--add-dir`) | `claude_cli.py` |
| Сетевому пользователю не выдаются `write_text` / `make_dir` / `delete_file` | `claude_cli.py`, `agent.py`, `mcp_guard.py` |
| MCP-порт: только приватные адреса и только с `Bearer`-токеном | `mcp_guard.py` |
| Не больше `CLAUDE_MAX_PARALLEL` запросов к подписке одновременно | `claude_cli.py` |
| Кто, откуда и что спрашивал | `data\chat_audit.log`, `data\mcp_access.log` |

`D:\Общая_Рабочая` — только чтение при любом способе подключения.
Файл `.env` не отдаётся ни одним инструментом.

## 6. Если не работает

**«Claude CLI есть, но вход не выполнен».**
На сервере выполнить `claude login`.

**Claude долго молчит или ругается на сеть.**
Не поднялся прокси-мост. Проверить порт: `netstat -ano | findstr 17880`.
Лог — `data\claude_proxy.log`.

**«Claude сейчас занят другими запросами».**
Упёрлись в `CLAUDE_MAX_PARALLEL`. Подождать или поднять значение в `.env`.

**Лимит подписки исчерпан.**
Переключиться на «Локальный ИИ» — он не зависит от подписки и лимитов.

**Сайт не открывается с другого компьютера.**
Порт закрыт брандмауэром: запустить `start.bat` от администратора.

**Адрес перестал открываться после перезагрузки.**
DHCP выдал серверу другой IP. Новый покажет `python net.py`.
Чтобы не повторялось — закрепить адрес за сервером в роутере.
